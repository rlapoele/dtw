## Implementation and provenance

The 35-line adapter reuses frozen `makeCodec` and `preflight`; no codec copy or
existing-code edits. A shared description guard inspects own data descriptors,
uses JavaScript string `.length` and rejects above 1,024 without coercion, trimming,
normalization or truncation. Encode preflights before the new guard; decode first
runs all existing strict admission checks. Error precedence otherwise remains
base-owned; a malformed candidate with multiple errors need not report this
field-specific error first.

Reused dependency: already installed Stage A **jsonc-parser 3.3.1**, package main
`lib/umd/main.js`. The Stage A package/lock, installed dependency metadata and all
UMD JavaScript files are hashed with reused codec/fixtures and governing documents
in [manifest.json](manifest.json). No root or isolated package was added/changed,
and no installation occurred. All old research/evidence remains unchanged.
The manifest explicitly excludes itself, this report, ignored runtime logs and
unrelated repository files; it hashes every new executable and the criteria README.

## Limits and handoff

This qualifies two research codec entry points only. Synthetic caller preservation
is not proof of actual application atomicity. Authoring operations, retained load,
backup generation/download and staged restore integration/UI are unimplemented
and unqualified by this work. No IndexedDB, browser, native selection/copy, Safari,
performance, memory, support-baseline, accessibility or production suite was run.
No claim closes those Increment 007 gates. The retired long-description fixture and
`exactBytes()` fixture remain untouched and were not used. Whole-project resource
boundaries beyond the selected generic strings were not rerun. Arbitrary proxy
traps remain outside the frozen preflight's synthetic plain-data claims.
